# 관성 구간 리드인 (설계)

날짜: 2026-10-14 · 상태: 초안 (사용자 합의: "조용한 지점까지 거슬러 올라가기" + "조각마다 사람이 고칠 수 있게", 판정 보완 포함)
선행: `2026-10-12-restpose-prepend-design.md` (기본자세 덧붙이기)

## 문제

기본자세 덧붙이기는 차렷 → 조각 첫 프레임으로 바로 전이한다. 빠르게 움직이는 도중에 자른 조각은 전이 끝에서 큰 속도를 받아야 해서 무리가 생긴다. 학습 정의서는 전이와 조각 사이에 **관성 구간**(자른 위치 바로 앞의 원본 모션)을 두도록 한다.

정의서 값 중 관성 구간 길이는 "예시 0.5초, 미정, 조각마다 바꿀 수 있어야 함"이다. 실제 곡(`Track2_FINAL_0909.csv`)에서 필요한 길이는 0초에서 1.3초까지 지점마다 달라서 고정 길이는 맞지 않는다.

## 결정

1. 덧붙이기 리드인을 세 구간으로 나눈다: **차렷 정지 → 전이 → 관성(원본) → 조각**.
2. 관성 길이는 자동 판정(아래)을 기본값으로 쓰고, 조각마다 사람이 바꿀 수 있다.
3. 차렷 정지 길이와 전이 길이도 조각마다 바꿀 수 있다. 전이 길이에는 관절 속도 한계로 정하는 자동 옵션이 있다.
4. 적용 범위는 지금과 같다: 클립 프리뷰와 그 조각의 CSV(와 그 CSV로 하는 물리 검증)만. 메인 타임라인 재생은 원본.
5. 덮어쓰기(`restPose: true`)는 이번 범위가 아니다. 지금 동작 그대로 둔다.

## 리드인 구성 (덧붙이기)

자른 위치를 클립 프레임 `c = trimIn`, 관성 길이를 `L`, 정지 `H`, 전이 `B`라 하면:

| CSV 행 | 내용 |
|---|---|
| `0 … H−1` | 차렷 정지 (`RobotDef.rest`) |
| `H … H+B−1` | 전이: 차렷(속도 0) → 클립 프레임 `c−L`의 값·속도로 3차 Hermite, URDF 한계로 자름 |
| `H+B … H+B+L−1` | 관성: 원본 클립 프레임 `c−L … c−1` 그대로 |
| `H+B+L …` | 조각 (원본 `c … trimOut−1`) |

- 리드인 길이 `lead = H + B + L`. 지금의 `REST_PREPEND = 90` 고정값은 이 값으로 바뀐다.
- 파생 클립: `prependRestPose(clip, def, a = c − L, H, B)`. 클립 프레임 `a` 앞에 `H+B` 프레임을 넣고 `a`부터는 그대로 뒤로 민다. 관성 구간은 원본 프레임이 그대로 이어지므로 "전이 → 관성"의 연결이 곧 지금의 "전이 → 조각" 연결과 같은 방식이 된다.
- 루트 x·y·yaw: 정지·전이 동안 클립 프레임 `a`(관성 시작) 값에 고정(현재 동작 유지, 2026-10-13 사용자 확정). 관성 구간부터는 원본 이동이 그대로 나온다.
- `L`은 `c`보다 클 수 없다(클립 앞에 원본이 없음).

## 관성 길이 자동 판정

원본 클립에서 프레임마다 **움직임 양** `E(f)`를 잰다.

- 관절: `Σ w_j · |q_j(f+1) − q_j(f)| · 60` (rad/s). 가중치 `w`: 다리·허리(hip, knee, ankle, waist; GO2는 모든 다리 관절) 1, 팔(shoulder, elbow) 0.5, 손목 0.2.
- 루트: `3 · |골반 위치 변화| · 60` (m/s) + `|yaw 변화| · 60` (rad/s).
- 9프레임 이동 평균으로 잔떨림을 없앤다.
- 조용함 기준 `Q` = 그 클립 전체 `E`의 하위 20% 값. 곡마다 자동으로 정해진다.

판정 (최대 범위 `MAX = 90`프레임 = 1.5초, 클립 앞 끝을 넘지 않음):

1. `E(c) ≤ Q` → `L = 0`, 이유 **멈춤**.
2. `c`에서 한 프레임씩 거꾸로 가다가 처음 만나는 프레임 `f`:
   - `E(f) ≤ Q` → `L = c − f`, 이유 **조용한 지점**.
   - `f`가 국소 최소이고 `E(f) ≤ 0.3 · E(c)` → `L = c − f`, 이유 **움직임 바닥**.
3. 못 찾으면 범위 `[c − MAX, c]`에서 `E`가 가장 작은 프레임 `m`(c 자신 포함)을 쓴다. `L = c − m`.
   - `E(m) ≤ 0.5 · E(c)` 또는 `E(m) ≤ 2Q` → 이유 **범위 내 최소**.
   - 아니면 이유 **검토 필요** (계속 빠르게 움직이는 구간. 사람이 확인).
4. `c = 0` → `L = 0`, 이유 **앞에 원본 없음**.

보완 이유: 처음 판정은 "못 찾으면 범위 내 최소"만 있어서 40초 지점이 0.13초(시작 움직임 11.9, 자른 지점 20.3)로 나왔다. 빠른 상태에서 전이를 받는 셈이라 "검토 필요" 표시를 더했다. 범위를 다 쓰는 안은 시작 움직임이 오히려 더 큰 경우(36.8 > 20.3)가 있어 버렸다.

## 전이 길이 자동 (옵션)

- 관절마다 전이 곡선(차렷 → 관성 시작 값·속도)의 최고 속도가 URDF `velocity` 한계의 50% 이하가 되는 가장 짧은 `B`를 찾는다. 후보 0.25초 ~ 3초, 6프레임 간격.
- 3초로도 안 되면 3초를 쓰고 이유 **속도 한계 초과**를 띄운다(내보내기 검사의 속도 경고와 같은 기준으로 다시 확인됨).

## 저장

`Item`에 선택 필드를 더한다. 없으면 기본값이라 기존 파일·기존 앱과 호환된다.

```ts
restHold?: number            // 차렷 정지 프레임, 기본 30
restBlend?: number | 'auto'  // 전이 프레임, 기본 60
inertia?: number             // 관성 프레임, 없으면 자동 판정
```

- 범위: 정지 0~180, 전이 0~180(0 = 순간 전환, 설정 줄에 ⚠·내보내기 속도 경고), 관성 0~min(180, trimIn). 정수 프레임. 전이 자동은 15~180에서 찾음.
- 설정 줄은 한 줄에 한 항목(기본자세 → 전이 → 관성 순서), 항목마다 `✕`(없애기 = 0초, 이미 0이면 비활성). (2026-10-14 사용자 요청)
- `restPose !== 'prepend'`이면 무시한다. 덧붙이기를 해제해도 값은 남겨 두어 다시 켜면 그대로 쓴다.
- `projectFile` 검증에 추가.

## 전이 중 발 고정 (2026-10-14)

사용자: 내보낸 파일에서 전이 동안 발이 드리프트함, "드리프트 하면 안된다". 관절만 보간하면 차렷(두 발 모음)에서 넓은 시작 자세로 갈 때 발이 바닥을 약 0.3 m 미끄러졌다.

- 발 계획(`stepPlan`): 움직일 필요가 없는 발(1 cm·0.05 rad 미만)은 제자리, 움직여야 하는 발은 먼 것부터 하나씩 전이의 [0.1, 0.9]를 나눈 자기 구간에서 들어(가운데 5 cm) 모션 첫 프레임 자리에 내려놓는다. G1은 발 위치+기울기, GO2는 발끝 위치.
- 전이 0(순간 전환)·1프레임이면 IK 없음.

## 전이→관성에서 발 순간이동 (2026-10-14, 2차)

사용자: `G1_Track2_FINAL_0909_4.csv`에서 "전이에서 관성으로 넘어갈 때 발이 순간이동", "오래 걸려도 확실히, 앞으로 자를 때 이런 일 없도록". 원인: 관성이 왼발이 공중(12 cm)에 있는 프레임에서 시작 → 전이가 발을 공중에 내려놓고 0.5초 멈췄다가 관성에서 갑자기 원래 속도로 움직임.

바뀐 규칙
- **관성 자동 판정은 두 발이 딛고 선 프레임만**(`legIk.footContact`): 발목이 그 클립 바닥(발 높이 하위 2%) + 4 cm 이내, 발 속도 0.12 m/s 미만, 골반이 차렷 높이의 절반 이상(앉거나 누운 자세 제외). 1.5초 안에 없으면 3초까지('두 발 딛는 지점(1.5초 넘게 앞)'), 그래도 없으면 '발이 떠 있음 · 검토 필요'.
- 리드인 상자 경고: 관성 시작 프레임에서 발이 떠 있으면(직접 넣은 값 포함) ⚠, 전이가 걸음에 비해 짧으면(발 1.5 m/s 초과) '⚠ 걸음이 빠름'. 전이 자동은 걸음 시간(발 1.2 m/s 이하)까지 확보.
- 걸음 계획(`stepPlan`): 발마다 [0.1, 1] 구간을 걸음 길이에 비례해 나눠 차례로, 마지막 발은 모션 시작까지. 들어 올린 뒤 이동하고 이동을 마친 뒤 내려놓음(각 15%), 높이 2~5 cm(걸음 길이에 비례), 내려놓을 때 수직 속도 0. 공중 발판(모션 시작에서 떠 있는 발)만 모션 속도로 이어 들어감. 계획 경로는 두 발판 중 낮은 쪽 아래로 내려가지 않음.
- 골반: 높이는 전이 앞쪽 절반에 모션 높이로(먼저 앉고 걸음), 기울기는 걸음과 함께 끝까지. 전이 곡선(`easeInto`)은 끝에서 모션 속도로 들어가되 그 영향은 마지막 약 10프레임으로 제한(긴 전이에서 크게 출렁이지 않음). 다리가 발판에 닿지 않으면(엉덩이~발판 > 다리 길이) 필요한 만큼만 골반을 부드럽게 낮춤(최대 15 cm, 앞뒤 끝 0).
- 다리 IK 시작값은 보간 각도(무릎이 앞으로 굽는 쪽 유지), 무릎이 펴져 있으면 0.3 rad에서 시작.

검증: `src/model/leadIn.sweep.test.ts` — 저장소 샘플 Track1을 400프레임마다 잘라 전이 1초·0.5초·2초·자동으로 기본자세+전이와 이음새를 검사(발 미끄러짐 3 mm 미만, 공중 정지 3프레임 이하, 바닥 아래 8 mm 미만, 관절 속도 한계 이하, 발 가속 한도, '발이 떠 있음'/'걸음이 빠름'은 경고가 켜졌는지). 사용자 곡 Track2도 59곳에서 같은 검사 통과(공중 도약 중인 1곳은 경고). 사용자 사례(2043)는 공중 정지 30프레임 → 0, 이음새 발 가속 21 → 리드인 안에서 튐 없음.
