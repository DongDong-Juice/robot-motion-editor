# 로봇 모션 편집기 설계

- 날짜: 2026-10-07
- 상태: 승인됨 (구현 계획 작성 전)

## 1. 목적

Unitree **G1(휴머노이드, 29 DoF)** 과 **GO2(사족, 12 DoF)** 의 모션을 키프레임·타임라인으로 편집하고, 강화학습(모션 모방)용 **CSV로 클립 단위 내보내기** 하는 웹 편집기.
레이아웃은 프리미어 프로 / 파이널컷 계열.

### 범위

| 포함 | 제외 (추후) |
|---|---|
| G1·GO2 한 프로젝트·한 무대에서 동시 편집 | ROS 연동, 실로봇/시뮬레이터 전송 |
| 관절·루트 키프레임, 보간, 그래프(커브) 에디터 | 학습 PC로 파일 전송 |
| 3D 무대 뷰어 + 관절 회전 기즈모 | IK, 발 접지 유지 |
| 시퀀스·클립(중첩 시퀀스)·크로스페이드 | 충돌 판정 |
| 참조 영상 트랙 | fps 변경 (60 고정) |
| 마커, In/Out | 키 감소(커브 단순화) |
| 클립 단위 CSV 내보내기 + 검증, CSV 가져오기 | Tauri/Electron 패키징 (구조만 대비) |

### 성공 기준

1. G1, GO2 액터를 한 무대에 배치하고 동선(루트 궤적)을 함께 확인할 수 있다.
2. 시퀀스의 각 모션 클립을 Unitree 형식 CSV(60fps, 헤더 없음)로 내보낼 수 있다.
3. 내보낸 CSV는 뷰어에서 보이는 포즈와 프레임 단위로 일치한다 (같은 `evaluate` 함수 사용).
4. 관절 한계·속도 초과, 루트 급변이 내보내기 전에 경고된다.

## 2. 기술 스택

- Vite + React + TypeScript, `three`, `zustand`. 다른 런타임 의존성 없음.
- 브라우저 로컬 실행. 파일 입출력은 File System Access API, 모두 `src/fileio.ts` 경유.
- 추후 Tauri/Electron 래핑 시 `fileio.ts`만 교체. (Windows Tauri = WebView2 → three.js·MP4 동작. 리눅스 데스크톱 목표면 Electron 권장.)

- **액터** = 로봇 인스턴스(G1 #1, GO2 #1, G1 #2 …). 무대 배치(x, y, yaw)와 색을 가진다.
- 액터마다 모션 트랙 1개. 클립은 로봇 타입을 가지며 같은 타입 트랙에만 놓인다.
- 클립 보기에서 다른 액터는 무대에 반투명 고스트로 표시(선택 불가).
- 관절 그룹: G1 = 루트, 왼다리, 오른다리, 허리, 왼팔, 오른팔. GO2 = 루트, FL, FR, RL, RR.
- 패널은 드래그로 크기 조절만. 도킹/분리 없음.

## 4. 데이터 모델

프로젝트 = JSON 파일 1개 (`*.motion.json`).

```ts
Project  { version: 1, fps: 60,
           actors: Actor[], clips: Record<id, Clip>, media: Media[], sequence: Sequence }
Actor    { id, name, robot: 'g1'|'go2', color, placement: { x, y, yaw } }
Clip     { id, name, robot, length /*frames*/, channels: Record<channelName, Curve> }
Curve    { keys: Key[] }                     // f 오름차순
Key      { f /*정수 프레임*/, v, interp: 'linear'|'bezier'|'hold',
           inTan: { df, dv }, outTan: { df, dv } }
Sequence { tracks: Track[], markers: { f, name }[], inF, outF }
Track    { id, kind: 'video'|'motion', actorId?, hidden, locked, items: Item[] }
Item     { id, refId /*clipId|mediaId*/, start, trimIn, trimOut }
Media    { id, name, durationF }             // 경로 미저장 → 열 때 재연결
```

- 채널: `root.x/y/z`(m), `root.roll/pitch/yaw`(rad), URDF 관절 이름(rad).
  루트 회전은 편집용 오일러, 출력 시 쿼터니언(xyzw).
- `interp`는 해당 키에서 다음 키까지 구간에 적용. "이즈" = 평평한 기본 탄젠트의 `bezier`.
- 키가 없는 채널 값은 0 (루트 z는 로봇 기본 높이: URDF 기준 서 있는 자세 높이).
- **클립 재사용 = 공유**: 같은 클립을 여러 번 배치하면 내부 편집이 모두에 반영.
- **크로스페이드**: 같은 트랙에서 두 Item이 겹친 구간 = 블렌드 구간. 가중치 선형, 관절·위치는 lerp, 루트 회전은 slerp.
- **루트 이어붙이기**: 뒤 Item의 루트 x, y, yaw를 앞 Item 블렌드 시작 시점의 루트 포즈 기준으로 변환 (z, roll, pitch는 그대로). 첫 Item은 액터 배치 기준.
- **빈 구간**: 트랙에서 클립 없는 프레임은 직전 포즈 유지 (맨 앞이면 첫 클립 첫 포즈).
- 핵심 함수: `evaluate(project, actorId, frame) → { rootPos, rootQuat, q[] }` (무대 월드 좌표).
  뷰어·내보내기 모두 이 함수만 사용.

### 로봇 정의 (`RobotDef`)

- G1: `assets/g1-assets/g1_model.json`(링크·관절 트리, 한계) + `g1_meshes.json`(base64 `pos`/`idx` 메시).
  `g1_29dof.urdf`가 참조하는 `meshes/*.STL` 폴더는 없음 → JSON 사용.
- GO2: unitree_ros `robots/go2_description` URDF+메시를 `tools/urdf_to_json.py`로 G1과 동일 포맷 변환.
- G1 에셋이 부족하면 unitree_ros `robots/g1_description`에서 보충.
- **CSV 관절 열 순서 = URDF에 등장하는 revolute 관절 순서.** 구현 시 Unitree 데이터셋 순서와 대조해 확정.

## 5. 편집 동작

**무대 뷰어**
- 오비트/팬/줌, 정면·측면·탑 뷰 단축키.
- 링크 클릭 → 부모 관절 선택 → 관절 축 회전 링 기즈모, URDF 한계로 클램프.
- 루트 클릭 → 이동+회전 기즈모.
- 자동 키 토글: 켜져 있으면 값 변경 시 재생헤드 프레임에 키 생성/수정.
- 액터별 루트 궤적선(바닥 투영) + 재생헤드 위치 점.

**인스펙터**
- 관절 슬라이더 + 숫자 입력(도/rad 토글), 한계 근접 시 색 변화.
- 이전/다음 키 이동, 키 추가/삭제, 그룹 일괄 키.
- 액터 배치(x, y, yaw), 색.

**트랙 보기**
- 키 선택(클릭, Shift 추가, 박스), 드래그 이동(프레임 스냅), 복사/붙여넣기(재생헤드 기준), Delete.
- 그룹 행 요약 키 드래그 = 하위 키 일괄 이동.
- 우클릭 → 보간(선형/이즈/홀드).

**그래프 보기**
- 선택 채널 커브 겹쳐 표시(색 구분). 키·베지어 핸들 드래그, 핸들 연동(Alt = 분리). F = 맞춤.
- URDF 한계 가로 점선, 속도 한계 초과 구간 빨간색.

**시퀀스 편집**
- 프로젝트 패널 → 트랙 드래그로 배치 (로봇 타입 불일치 거부).
- 클립 이동, 끝 드래그 트림, C = 재생헤드에서 자르기, 겹치면 자동 크로스페이드.
- 더블클릭 = 클립 보기, Esc/브레드크럼 = 복귀.
- I/O = In/Out, M = 마커.
- Space 재생/정지, ←/→ 1프레임, Shift+←/→ 10프레임, Ctrl+Z / Ctrl+Shift+Z.

**참조 영상**
- V1 트랙에서 이동·트림. 뷰어 오버레이(투명도) 또는 분할 표시.
- 재생/스크럽 시 `video.currentTime`을 재생헤드에 동기화.

## 6. 내보내기 · 가져오기 · 검증

### CSV 내보내기 (클립 단위)

- 대화상자: 액터별 모션 트랙의 Item 목록을 체크박스로 선택 (기본 전체).
- **Item 1개 = CSV 1개.** 시퀀스에 놓인 그대로 평가: 트림·루트 이어붙이기 반영, 크로스페이드 구간은 블렌드된 포즈.
  프레임 범위 = Item의 시퀀스 상 시작~끝(겹침 포함).
- 파일명 `<로봇>_<클립이름>.csv`; 액터가 같은 로봇 여러 개면 `<액터이름>_<클립이름>.csv`; 중복 시 `_2`, `_3`.
- 루트 좌표 선택:
  - **로컬(기본)**: 해당 CSV 첫 프레임의 x, y, yaw가 0이 되도록 변환. z, roll, pitch 유지.
  - **월드**: 무대 좌표 그대로.
- 형식: 헤더 없음, 60fps, 행 = `x,y,z,qx,qy,qz,qw,q1..qN` (G1 N=29 → 36열, GO2 N=12 → 19열), 소수 6자리, m/rad.
- 쿼터니언: 매 프레임 정규화, 이전 프레임과 내적이 음수면 부호 반전(연속성).

### 검증 (Item별, 경고만 · 차단 없음)

| 항목 | 기준 |
|---|---|
| 관절 한계 초과 | URDF `lower/upper` 밖 |
| 관절 속도 초과 | \|Δq\| × 60 > URDF `velocity` |
| 루트 급변 | 프레임당 위치 > 0.05 m 또는 회전 > 0.1 rad |
| 빈 구간 | 트랙에 클립 없는 프레임 포함 |

경고 클릭 → 해당 프레임으로 재생헤드 이동 + 채널 선택. "그래도 내보내기" 가능.

### CSV 가져오기

- Unitree 형식 CSV → 새 클립. 매 프레임 키, 선형 보간.
- 원본 fps(30/60) 지정, 30fps는 60fps로 리샘플.

## 7. 모듈 구조

```
src/
  robot/      RobotDef 로드, 메시 디코딩, 관절 순서·한계·그룹
  model/      types.ts, curve.ts, evaluate.ts   (순수 함수, UI 의존 없음)
  store/      zustand 상태, 실행취소 = 프로젝트 스냅샷 스택
  viewer/     three.js 무대, 메시, 기즈모, 궤적, 고스트, 영상 오버레이
  timeline/   Canvas 2D: 시퀀스 / 트랙 / 그래프
  inspector/  슬라이더, 보간, 배치
  export/     csv.ts, validate.ts, import.ts
  fileio.ts   열기·저장·CSV 쓰기 (래퍼 교체 지점)
tools/
  urdf_to_json.py   URDF + 메시 → RobotDef JSON
```

- 타임라인은 Canvas 2D (30트랙 × 다수 키 성능).
- 실행취소는 스냅샷 스택 — 프로젝트가 커지면 패치 기반으로 교체.

## 8. 테스트

  - 검증 경고 검출
- **Playwright 스모크 1개**: G1·GO2 로드 → 키 추가 → 클립 내보내기 → CSV 형식 확인.
- 기준 데이터: G1 기본 자세(전 관절 0) 내보내기 → URDF 관절 순서와 대조.

## 9. 비주얼 방향

- 주제: 로봇 촬영 스튜디오 무대. **강조는 무대 뷰어 한 곳** — 바닥 치수 그리드, 액터별 동선을 바닥 테이프 마킹처럼. 나머지 패널은 조용히.
- 색 토큰:
  - `--bg #22262D`, `--panel #2B3038`, `--line #3B424D`, `--text #D5DAE1`
  - `--accent #F0A43A` (재생헤드·선택, 산업 안전색 앰버)
  - 액터 기본색: G1 `#58B4D1`, GO2 `#C9D65A` (변경 가능)
  - 키프레임: 기본 흰색, 선택 앰버
- 서체: IBM Plex Sans KR 단일. 타임코드·수치는 `font-variant-numeric: tabular-nums`.
- 원칙: 대문자 라벨·카드 그림자·그라데이션 없음. 패널 구분은 1px 선과 명도 차. 모션은 사용자 조작 반응(펼침, 스냅)에만.
- 품질 기준: 키보드 포커스 표시, `prefers-reduced-motion` 존중, 대비 확보.

## 10. 구현 단계

1. **M1 코어**: RobotDef(G1, GO2 변환), 무대 뷰어·기즈모, 액터, 클립 1개 편집(트랙·그래프·보간), 클립 CSV 내보내기·검증.
   M1에서는 액터당 클립 1개를 트랙 시작에 놓은 Item 1개로 취급 → 같은 `evaluate`/내보내기 경로를 그대로 사용.
2. **M2 시퀀스**: 시퀀스 트랙, 클립 배치·트림·자르기, 중첩 클립 보기, 크로스페이드, 루트 이어붙이기, 마커·In/Out, CSV 가져오기, 프로젝트 저장/열기.
3. **M3 참조 영상**: 미디어 가져오기, V1 트랙, 오버레이/분할, 동기화.
