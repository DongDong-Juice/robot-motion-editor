# 3D 끌기: 배치 이동 · GO2 걸어가기

## 목적

메인 3D에서 로봇을 잡아 끌 때 (1) 기본은 키 없이 로봇 전체 위치(배치)만 옮기고, (2) `배치 이동` 토글을 켜면 GO2가 진행 방향을 바라보며
끌어 놓은 지점까지 걸어가는 클립을 실제 로그로 만들어 트랙 끝에 붙인다. 공연 동선을 3D에서 바로 찍기 위함.

## 확정 사항 (사용자)

- 토글 꺼짐 끌기 = **로봇 전체 배치**(`Actor.placement` x·y) 이동, 키·수정 층 없음. G1·GO2 공통(지난 "그 프레임 root.x·y" 끌기를 대체).
- `배치 이동` 토글: 프리뷰 오른쪽 위 플로팅 툴바(`pv-tools`), 메인 3D만, 기본 꺼짐, 저장 안 함.
- 토글 켜짐 + GO2 끌기 = 걷기 클립 생성 → 그 GO2 **트랙 끝에 붙임**, 출발 = 트랙 마지막 프레임의 자리·방향.
- 걷기 = **실제 로그**(Move forward·Rotate 블럭)로 만들고 **도착점은 정확히** 맞춤.
- 사용자 승인 가정: G1 끌기도 배치 이동, |θ| < 60°면 제자리 회전 없이 걷기 시작 구간에서 서서히 방향 전환(발 약간 미끄러짐 허용), 너무 가까우면 안내만.

## 범위 밖

- 곡선 경로·경유지 한 번에 여러 개(여러 번 끌면 이어짐으로 대신), G1 걷기, 걷기 속도 선택.
- 클립 프리뷰·⇄비교·구간 프리뷰 창의 끌기(없음).

## 1. 기본 끌기 (토글 꺼짐, G1·GO2)

- 메인 3D에서 로봇 몸을 왼쪽 버튼으로 눌러 4 px 넘게 끌면 바닥 평면(z = 0) 위 이동량 (dx, dy)를 그 액터의 시작 배치에 더해 `setPlacement(actorId, { x, y })`. 끄는 동안 바로 반영, 놓으면 제스처 1회 = 실행취소 1번.
- 기존 끌기(`editPose` root.x·y)는 제거. 클릭만(4 px 안) = 관절 선택, 빈 곳 = 카메라, 기즈모 = 기즈모, 끄는 중 Ctrl+Z = 그 끌기만 취소 — 지금과 같음.
- 시작 안 하는 경우: 트랙 잠김(`trackLocked`), 숨김, 클립 편집 모드, 재생 중. (배치는 조각 단위가 아니므로 크로스페이드·스티치·조각 밖 조건은 없음.)

## 2. 배치 이동 토글

- 버튼 `배치 이동`(`aria-pressed`), `pv-tools`에서 `무대` 바로 뒤, 메인 창만. 스토어 UI 필드 `walkMode: boolean`(기본 false, 저장 안 함).
- 켜면: 끌 수 있는 GO2가 메인 3D에서 트랙 끝 자세로 보이도록 재생헤드를 **선택된 GO2**(없으면 첫 GO2)의 트랙 끝 − 1 프레임으로 옮김.
- 켜진 상태에서 **GO2**를 끌면:
  - 로봇은 움직이지 않음. 출발점(그 GO2 트랙 마지막 프레임의 월드 x·y)에서 커서의 바닥 점까지 `--accent` 점선 + 도착 원 표시.
  - 놓으면 `walkToClip`으로 클립 생성 → `appendClip(actorId, clip)`(트랙 끝, 기존 이어 붙이기 규칙으로 출발 자리·방향에 맞춰짐). 클립 추가와 붙이기 = 실행취소 1번. 재생헤드를 새 트랙 끝 − 1로.
  - 실패(너무 가까움 등) → 아무것도 만들지 않고 시퀀스 메시지 줄(`.seq-msg`)에 안내.
- 켜진 상태에서 G1을 끌면 1번 규칙(배치 이동).
- 트랙이 없는 GO2(빈 액터)는 출발 = 배치 위치·방향, 클립은 0프레임부터.

## 3. 걷기 클립 (`src/go2blocks/walkTo.ts`, 순수 함수)

`walkToClip(rot: Template, move: Template, start: { x, y, yaw }, target: { x, y }, defs): { clip } | { error: string }`
(`Template` = 블럭 CSV를 읽은 `{ fps, poses }`, Rotate·Move 블럭 정의는 `GO2_BLOCKS`에서)

1. 출발 로컬 좌표에서 목표: 거리 d, 방향 θ(−180°~180°, 왼쪽 +).
2. **걷기 부분**: Move 블럭으로 `buildBlockClip`과 같은 방식(head + loop × n + tail)의 포즈를 만들되 n = d에 가장 가까운 걸음 수, 그 결과 진행 거리 a에 대해 각 프레임 루트의 진행 방향 성분을 d / a배(나머지 성분·높이·자세·관절은 그대로). 비율이 [0.8, 1.2] 밖이면 n을 바꿔 안으로; 어떤 n ≥ 1로도 0.8배 이상이 안 되면(d < 최소 거리 × 0.8) `{ error: '이 거리는 너무 가깝습니다 (최소 약 X m)' }`(X = 최소 걷기 거리 × 0.8, 소수 1자리).
3. **방향**:
   - |θ| ≥ 60°: 걷기 앞에 Rotate 블럭(θ 부호로 좌/우)의 head + loop × n + tail, n = |θ|에 가장 가까운 걸음 수, 각 프레임 yaw를 회전 시작 기준으로 θ / 실제 회전각 배. 걷기 부분은 회전 끝 자세(자리·방향 θ)에 이어 붙임(이음매는 기존 `blendPose` 5프레임).
   - |θ| < 60°: 제자리 회전 없음. 걷기 부분 전체를 원점 기준 θ만큼 돌리되 head 구간 동안 0 → θ로 부드럽게(smoothstep) 바뀌는 yaw 오프셋을 적용(루트 위치는 그 시점 방향으로 진행).
4. 최종 포즈를 60 fps로(`posesToClip`), 첫 프레임 = 원점·yaw 0(출발 방향), 마지막 프레임 루트 = (d cos θ, d sin θ), 방향 = θ.
5. 클립 이름 `Walk_<d 소수 1자리>m_<θ 정수>deg`(예 `Walk_2.3m_45deg`), 로봇 `go2`.

## 테스트

- 단위(`walkTo.test.ts`, 실제 `리얼데이터/move.csv`·`rotate.csv`): 여러 (d, θ) — (2, 0°), (3, 45°), (2.5, −90°), (4, 180°) — 마지막 프레임 위치 오차 < 0.01 m, 방향 오차 < 2°, 첫 프레임 원점·0°, 관절은 로그 값 그대로(관절 한계 안), 너무 가까운 d → error.
- 스토어/액션: 배치 끌기 = `setPlacement` 1회 실행취소, 키 수 변화 없음.
- e2e(`e2e/walkTo.spec.ts`): 토글 꺼짐 끌기 → placement 바뀜·수정 키 0; 토글 켜짐 GO2 끌기 → 트랙 조각 +1, 새 조각 마지막 프레임 월드 위치 ≈ 놓은 바닥 점(±0.05 m), Ctrl+Z 1번 → 조각 원래대로; 가까운 끌기 → 조각 그대로 + 안내 문구. 기존 `poseDrag.spec.ts`는 배치 이동 기준으로 갱신.
